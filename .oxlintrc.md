# Why `.oxlintrc.json` looks like this

The linter is [oxlint](https://oxc.rs) (same rules as ESLint, written in Rust,
so it runs in ~1s instead of ~30s).

## `react/rules-of-hooks`: **error**

Not negotiable. Conditional hooks are a real bug, not a style opinion — React
throws or silently mis-assigns state when they appear. This project had **three**
of them in `Modals.jsx` (a `if (!isOpen) return null;` sitting *above* three
`useState` calls), fixed on 2026-10.

## `react/only-export-components`: **warn**, with allowances

The rule exists to protect *React Fast Refresh* (hot module replacement): a file
that exports both components and ordinary values can be replaced by HMR only if
the exports line up, so React Refresh falls back to a **full page reload** on
every edit. That is a developer-experience cost, not a correctness cost.

`allowConstantExport: true` is the rule's own recommended setting — it permits
exporting `string` / `number` / `boolean` literals next to components.

`allowExportNames` names the exports this project deliberately keeps beside a
component. Each is checked against the rule's actual concern:

| Export | File | Why it is safe |
| --- | --- | --- |
| `useRoute` | `src/router.jsx` | A hook, not a component. React Refresh's convention is that `use*` exports are picked up normally. |
| `useStore`, `useLedger`, ~30 others | `src/store.jsx` | All hooks. Same reasoning: `use*` is the convention the rule and React Refresh both recognise. |
| `SEED` | `src/store.jsx` | Read-only fixture data. Moved to `src/data/seed.js` in 2026-10 so `scripts/verify-ledger.mjs` can import it under plain Node. |
| `INITIAL_AUDIT_LOGS` | `AuditLogView.jsx` | Fixed sample data — an array literal of objects, never mutated, never written to. |
| `INITIAL_RULES` | `RulesView.jsx` | Same. |

`INITIAL_CHART_OF_ACCOUNTS` is **no longer on this list**. It was a 28-row
fixture embedded in `ChartOfAccountsView.jsx`, with a typed-in balance on every
row — a second set of books that no transaction could touch. It now lives in
`src/data/chartOfAccounts.js`, shared with the Balance Sheet, the Profit & Loss
and the ledger, and its balances are derived. The allowance was removed rather
than kept, because the thing it permitted is the thing that was wrong.

The remaining `INITIAL_*` arrays would otherwise require moving fixture data
into separate modules to buy an HMR improvement that a developer editing them
anyway would never notice. They are constants in the true sense; the rule's own
name (`allowConstantExport`) says it should allow them — its implementation just
does not treat *array* literals as constants.

**Anything else is not on this list.** If a file starts exporting a function that
closes over component state, or a value that is mutated after import, it goes in
its own module — which is exactly why `money.js`, `hooks.jsx`, `routes.js` and
`ui.jsx` are four files rather than one.

## Adding a rule

```jsonc
"rules": {
  "no-console": "warn"
}
```

Severity: `"off"` / `"warn"` / `"error"`. `npm run lint` exits **0** when there
are warnings and **1** only on errors or a config that fails to parse — so a
green `npm run lint` means "no errors", not "no warnings". Check the counts with:

```sh
npm run lint 2>&1 | grep -c warning
```
